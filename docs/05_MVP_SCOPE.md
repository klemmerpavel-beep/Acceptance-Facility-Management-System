# Объём полевого испытания

Документ фиксирует, что именно проверяется на одном действующем объекте в течение месяца.
Он уже́ первой версии из `01_PROJECT.md`, раздел 6.1: там девять модулей, здесь — одна функция
и пять решений. Всё, что не названо ниже, в испытание не входит, хотя и входит в первую версию.

Отбор произведён по одному критерию: без чего невозможно измерить две определяющие метрики —
доля позиций, отмеченных в системе, от фактически выполненных (цель ≥ 80 %) и время прораба
на отметку одной позиции (цель ≤ 30 секунд).

## Ключевая функция

**Пакетная приёмка позиций раздела с фотофиксацией, порождающая начисление сдельной оплаты.**

Прораб открывает раздел, отмечает выполненные позиции, снимает помещение, подтверждает.
Тем же действием: начисляется оплата бригаде по ставке позиции со снимком ставки на момент
приёмки, уменьшается остаток текущего транша, позиция становится доступной для акта.

Проверяемые пороги: три касания на пакет; не более 30 секунд на позицию при десяти замерах
секундомером; не менее 80 % фактически выполненного отмечено в системе по сверке с прорабом.

## Пять малых решений

| № | Решение | Зачем в испытании |
|---|---|---|
| 1 | **Вход прораба по персональной ссылке** — без регистрации, пароля и кода из СМС; ссылка открывается сразу на разделах объекта | Заказчик не смог завершить регистрацию в продукте-конкуренте. Барьер входа снимается целиком, иначе метрика доли отмеченного измеряет не продукт, а порог освоения |
| 2 | **Импорт сметы из `.xlsx` с отчётом о расхождениях** | Единственный способ наполнить систему. Отчёт показывает недосчёт 438 800 ₽ в действующем файле до того, как принята первая позиция |
| 3 | **Сводка объекта: выполнено на сумму, остаток текущего транша, процент готовности**; транш заводится руководителем одним числом | Ровно та картина, ради которой руководитель открывает систему вечером. Без неё у руководителя нет причины заходить, и приёмка остаётся односторонней |
| 4 | **Свод начислений по бригаде** за транш, за неделю, всего по объекту | Единственный механизм удержания прораба: прекращение приёмки немедленно останавливает начисления |
| 5 | **Сторно руководителем с обязательной причиной** — обратная запись, не удаление | Без него первая же ошибка делает данные недостоверными, и прораб перестаёт отмечать |

## Действует с первого дня, но экраном не является

Разграничение доступа на уровне полей: `unit_wage`, `wage_total`, `profit`, `profit_pct`
не попадают в ответ сервера для роли `FOREMAN`. Проверяется тестом, который дёргает API
от имени прораба и убеждается, что полей нет в теле ответа.

## За пределами испытания

Акты выполненных работ и выгрузка в PDF, почтовый шлюз чеков, график производства работ,
клиентская проекция сметы как отдельный экран. Входят в первую версию, но для замера двух
определяющих метрик не нужны.
