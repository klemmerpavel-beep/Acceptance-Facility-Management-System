# ADR-0003. Шаблоны работ по виду поверхности вместо автосметы

| Параметр | Значение |
|---|---|
| Дата | 06.11.2026 |
| Фаза | 0 — аудит без изменения кода |
| Состояние продукта | ветка `main`, голова `053cd2c` |

| Связанные документы | ADR-0001 (порядок решений и обозначения), ADR-0002, `docs/discovery/ESTIMATE.md` |

**О слове.** «Шаблон работ» — название темы этого решения, а не слово продукта. Слово «шаблон» в
продукте занято дважды — эталонной книгой выгрузки и шаблонами документов, — и третьего значения ему
не даётся: «одно слово на одну вещь» (`apps/api/prisma/schema.prisma:240-242`). Ниже сущность называется
рабочим словом «набор работ»; слово экрана выбирает заказчик (вопрос второго раунда вместе с Д4).

раздел «Раунд 1 допроса фазы 0 переработки, 06.11.2026»). Исключения «автоматический расчёт сметы по

## Контекст

**Что есть в продукте.**

- Смета приходит импортом из книги с отчётом о расхождениях (БП-9, `docs/01_PROJECT.md:207`); позиция
  правится на месте с записью каждого поля в журнал, новую редакцию порождает только импорт
  (Р11, `docs/01_PROJECT.md:318`; `apps/api/src/estimates/estimates.service.ts:626-657`).
- Типовые сметы организации хранят разделы, наименования, единицы, цены, ставки и количества без
  помещений (`apps/api/prisma/schema.prisma:238-309`). Применяются только к объекту без сметы
  (`apps/api/src/blueprints/blueprints.service.ts:218-226`), только руководителем
  (`apps/api/src/estimates/estimates.controller.ts:47-49`; П-23).
- Подстановка величины помещения в количество позиции — по выбору человека, из перечня, подходящего
  единице: «м²» — площадь пола или стен, «м.п.» — периметр пола или потолка
  (`packages/domain/src/estimate.ts:385-388`; `docs/06_PLAN.md:334`).
- Справочник расценок объявлен в модели данных (`docs/01_PROJECT.md:182`), в схеме его нет; тип ремонта
  с тарифом за м² служит только ориентиру заявки (`apps/api/prisma/schema.prisma:1060-1079`).
  Канонических единиц девять, м³, кг и л среди них нет (`packages/importer/src/units.ts:16-19`).
- Роли методолога и сметчика нет (`apps/api/prisma/schema.prisma:36-41`).
- Этап графика ведёт раздел верхнего уровня, бригада этапа — получатель начисления; раздел без этапа
  с бригадой приёмку не проходит (`apps/api/src/stages/stages.service.ts:209-218`,
  `apps/api/src/acceptance/acceptance.service.ts:442-455`).

**Что предлагает бриф v2.0.** Технологические карты с формулами объёма, нормами времени и расхода,
коэффициентами отходов, кратностью слоёв, критериями приёмки; библиотека не меньше 40 карт; автосмета
с долей автоматических позиций не ниже 80 %; варианты «эконом / стандарт / премиум»; длительности графика
из норм; роль методолога, без которой блок не реализуется (бриф v2.0, §7.8.2, §8.5).

**Записанные решения.** «Автоматический расчёт сметы по дизайн-проекту» вне объёма: риск Г-4 — при
приемлемой для заказчика точности 70 % погрешность на смете 3,76 млн ₽ составляет ±1,1 млн ₽; шаблоны
ТЕР и ФЕР вне объёма (`docs/01_PROJECT.md:130`). Смета предварительна: в дизайн-проекте всегда есть
отклонения (`docs/01_PROJECT.md:70`).

## Рассмотренные варианты

| Вариант | Суть | Плюсы | Минусы |
|---|---|---|---|
| а | Исключение сохраняется: импорт, ручная правка, типовые сметы | Без работ | Обмер и смета связаны только ручной подстановкой по одной позиции |
| б | Наборы работ по виду поверхности: перечень позиций с ценой, ставкой и правилом количества «величина поверхности × коэффициент», применяемый к назначенной поверхности или помещению | Строится на типовых сметах и подстановке; без нормативных баз; погрешность ограничена погрешностью обмера, а не нормы | Не даёт вариантов, длительностей из норм и материалов по нормам расхода |
| в | Движок технологических карт по брифу | Полный блок U1 | Требует методолога в штате заказчика и библиотеки норм; при широком толковании отменяет исключение Г-4 |

## Предлагаемое решение

Вариант «б». Автосметы по дизайн-проекту, норм расхода, ТЕР и ФЕР нет; Г-4 остаётся вне объёма.

1. **Набор работ** (`WorkSet`, таблица `work_sets`): организация, имя (уникально в организации, как у
   типовой сметы, `apps/api/prisma/schema.prisma:264`), вид поверхности (пол, потолок, стены, одна
   стена, откосы — по ADR-0002), раздел сметы по имени.
2. **Строка набора** (`WorkSetItem`, таблица `work_set_items`): наименование, единица из справочника организации, цена и
   ставка в копейках, порядок, источник количества (площадь брутто, площадь нетто, периметр, откосы,
   «штук на поверхность») и коэффициент кратности в тысячных долях (два слоя — `2000`).
   Количество = `divideRoundHalfUp(величина × коэффициент, 1000)` — единственное правило округления
   (`packages/domain/src/money.ts:54-68`).
3. **Применение.** Руководитель выбирает в смете объекта помещение, поверхность и набор работ; служба
   добавляет позиции в действующую редакцию на месте (Р11), с `roomId` и адресом поверхности
   (ADR-0002, п. 3); каждая новая позиция пишет запись журнала в той же транзакции (БП-10, П-37,
   `apps/api/src/common/audit.service.ts:8-31`). Раздел ищется по имени среди разделов верхнего уровня;
   если его нет — заводится, и экран называет последствие: без этапа с бригадой раздел приёмку не
   пройдёт (`apps/api/src/acceptance/acceptance.service.ts:450-455`).
4. **Пересчёта нет.** Количество — копия, как при подстановке сегодня. Изменение обмера позиции не
   переписывает; признак «обмер изменился после подстановки» — вопрос второго раунда (Д4).
5. **Ведение наборов** — вкладка настроек рядом с «Типовыми сметами», только руководителю, тем же
   правилом, что у типовых смет (`@OwnerOnly`, `apps/api/src/common/roles.guard.ts:23-24`). Роль
   методолога не вводится.
6. **Без обмера по стенам** (ответ «а» или «б» по ADR-0002) набор применяется к помещению: видам «пол»,
   «потолок», «стены» хватает четырёх величин и нетто площади стен.
7. **Единицы** — канонические, без м³, кг и л: нормы расхода материалов не считаются.

## Последствия

- Смета остаётся предварительной и правится человеком; набор работ ускоряет заведение позиций, но факт
  по-прежнему даёт только приёмка (БП-1, `docs/01_PROJECT.md:199`).
- Не достигаются цели брифа: варианты «эконом / стандарт / премиум», длительности и связи графика из
  норм, метрика доли автоматических позиций (замечание к вопросу об автоматическом расчёте сметы,
  `docs/discovery/QUESTIONS.md`).
- Вторая заготовка рядом с типовой сметой: различие закрепляется словами — «типовая смета» заводит
  смету объекта целиком, «набор работ» добавляет позиции на поверхность действующей сметы.
- Затрагиваются: схема (две таблицы; миграция — после миграций ADR-0002, `docs/discovery/MIGRATION.md`,
  раздел 3.2), контракты, служба сметы, настройки,
  `verify-api` (права, журнал, количество из обмера), `verify-page`, двойник демонстрации и слепок.
- Оценка: 8–10 идеальных дней при поверхностях ADR-0002, на 1–2 дня меньше при наборе на помещение
  (`ESTIMATE.md`, раздел 3).

## Зависимости от решений

- Вопрос раунда 1 об автоматическом расчёте сметы (U1): выбор «а», «б» или «в» и толкование исключения
  Г-4.
- Вопрос раунда 1 о модели геометрии обмера (U1): поверхность как адрес набора работ (ADR-0002).
- Вопросы второго раунда: Д4 (шаблоны работ — на помещение или на поверхность; там же — слово экрана),
  Д5 (спецификация отделки), Д13 (длительности из норм — при «б» не вводятся).
