# ADR-0001. Порядок принятия решений при переработке

| Параметр | Значение |
|---|---|
| Дата | 06.11.2026 |
| Фаза | 0 — аудит без изменения кода |
| Состояние продукта | ветка `main`, голова `053cd2c` |
| Связанные документы | `docs/discovery/AS-IS.md`, `docs/discovery/GAP.md`, `docs/discovery/QUESTIONS.md`, `docs/discovery/MIGRATION.md`, `docs/discovery/ESTIMATE.md`, ADR-0002 — ADR-0008 |

**Обозначения, общие для ADR-0001 — ADR-0008.** «Заказчик» без уточнения — заказчик разработки,
принимающий решения и сливающий запросы (`docs/10_QUIZ.md:366`); роль `CLIENT` называется «заказчик
объекта» (`docs/01_PROJECT.md:54`). Продукт, с которым ведётся сверка, называется только «эталон» или
«референс» (`docs/06_PLAN.md:153`). Бриф v2.0 — внешний документ; ссылки на него даются номером
раздела, сам он в хранилище не переносится. «Не проверено» — утверждение, не подтверждённое чтением
кода или прогоном в фазе 0.

## Статус

Предложено. Решение повторяет действующие правила хранилища и распространяет их на бриф v2.0;
подтверждения заказчика требует часть о статусе брифа (вопрос раунда 1 о том, что из брифа v2.0
допускается в публичное хранилище).

## Контекст

1. **Источник правды по объёму один.** `docs/01_PROJECT.md` назван единственным источником правды по
   объёму; расширение объёма без явного решения запрещено, список исключённого — раздел 6.2
   (`docs/02_DEV_PROMPT.md:40`, `README.md:50-51`). Раздел 6.2 — закрытый список, любое добавление
   требует явного решения (`docs/01_PROJECT.md:234`). Противоречие промпта разработки и
   `01_PROJECT.md` — остановиться и спросить, приоритет у `01_PROJECT.md` (`docs/02_DEV_PROMPT.md:142`);
   «есть у референса» доводом не является (`docs/02_DEV_PROMPT.md:144`).
2. **Порядок работы до кода записан.** До кода — допрос скиллом `grilling`: раунды, весь фронтир
   сразу, вопросы пронумерованы, у каждого рекомендуемый ответ, затем ожидание ответов
   (`docs/02_DEV_PROMPT.md:13-15`); допрос повторяется перед каждым этапом с новыми развилками
   (`docs/02_DEV_PROMPT.md:70`).
3. **Порядок изменения документов записан.** `01_PROJECT.md` меняется новой редакцией с перечнем
   «Изменения редакции N» таблицей «Что изменено | Причина» (`docs/01_PROJECT.md:17-19`, образец —
   `docs/01_PROJECT.md:505-515`). Отмена прежнего решения называется прямо (`docs/01_PROJECT.md:57-61`).
   Ответы в `10_QUIZ.md` не переписываются (`docs/10_QUIZ.md:17-19`). Новый экран — сначала строка в
   `07_IA.md`, затем канва, затем код (`docs/07_IA.md:234`, `docs/03_DESIGN_SYSTEM.md:387`).
4. **Класс «решение заказчика» определён реестром.** Схема базы, денежные правила, объём,
   зависимость, отмена записанного решения не исполняются, а выносятся с вариантами и ценой
   (`docs/13_FULL_AUDIT.md:16-20`).
5. **Бриф v2.0 расходится с записанными решениями по 22 пунктам** (реестр `РБ-1` — `РБ-22`,
   `docs/discovery/GAP.md`, раздел 3): рабочие вне ввода данных (`docs/01_PROJECT.md:63`), работа без
   сети и нативные приложения (`docs/01_PROJECT.md:238-239`), электронная подпись, замечания с
   повторной приёмкой, автоматический расчёт сметы по дизайн-проекту, шаблоны ТЕР и ФЕР
   (`docs/01_PROJECT.md:130`), заказная работа под конкретного плательщика (`docs/01_PROJECT.md:246`).
6. **Внешний промпт к брифу задаёт правила, расходящиеся с правилами хранилища**: имя ветки
   `feature/<эпик>-<кратко>` против действующего образца `claude/<этап>-<кратко>` (`docs/06_PLAN.md:182`)
   и обратимые миграции против правила «миграции только вперёд» (`docs/02_DEV_PROMPT.md:112`,
   `apps/api/prisma/schema.prisma:7`); ввод зависимости обоснованием в архитектурном решении против
   класса «решение заказчика» (`docs/13_FULL_AUDIT.md:18-20`, `docs/02_DEV_PROMPT.md:128`).
7. **Ограничение на раскрытие.** С 02.10.2026 «наружу не выходит ничего от эталона — снимки, тексты,
   названия, логотип, разбор» (`docs/06_PLAN.md:153`; П-4, `docs/10_QUIZ.md:341`); название эталона в
   любом отслеживаемом файле роняет сборку (`scripts/verify-docs.mjs:655-672`). Хранилище публично
   вместе с историей (Р-24, `docs/01_PROJECT.md:316-317`).

## Рассмотренные варианты

| Вариант | Суть | Оценка |
|---|---|---|
| а | Бриф v2.0 — новый источник правды: блоки брифа исполняются по его фазам, `01_PROJECT.md` правится вдогонку | Отменяет `docs/02_DEV_PROMPT.md:40` и `docs/01_PROJECT.md:234` без решения заказчика; 22 расхождения `РБ-N` вошли бы в работу молча. Отвергнут |
| б | Бриф v2.0 — предложение. `01_PROJECT.md` остаётся источником правды; каждый блок брифа входит в работу только решением заказчика, записанным новой редакцией `01_PROJECT.md` после допроса | Совпадает с действующими правилами; цена — раунд допроса на каждый блок |
| в | Пересказ брифа отдельным документом в хранилище как второй источник требований | Второй источник рядом с единственным (`docs/02_DEV_PROMPT.md:40`); пересказ несёт сравнение с эталоном, рассыпанное по брифу (`docs/discovery/QUESTIONS.md`, вопрос о публичном хранилище). Отвергнут |

## Предлагаемое решение

Вариант «б». Порядок для каждого блока брифа v2.0:

1. **Сверка.** Блок сопоставляется с продуктом и записанными решениями (`GAP.md`); расхождение
   получает опознаватель `РБ-N`.
2. **Допрос.** Развилка выносится вопросом с вариантами, ценой и рекомендуемым ответом
   (`QUESTIONS.md`). Рекомендация не равна ответу; работа по вопросу без ответа не начинается.
3. **Архитектурное решение.** ADR этого каталога описывает устройство при рекомендуемом ответе и
   остаётся в статусе «Предложено» или «Требует решения заказчика», пока ответа нет. Статус
   «Принято» ставится только со ссылкой на ответ заказчика (номер вопроса и дата записи в
   `10_QUIZ.md` или в документе раунда).
4. **Новая редакция `01_PROJECT.md`.** Принятый блок входит в объём строкой раздела 6 и перечнем
   «Изменения редакции N»; отменённое решение зачёркивается с датой и основанием, а не удаляется.
   Затем — строка в `06_PLAN.md`, для экрана — строка в `07_IA.md` и артборд канвы.
5. **Ветка и запрос.** Работа ведётся по правилам хранилища: ветка `claude/<этап>-<кратко>`, запрос
   сливает заказчик (`docs/10_QUIZ.md:366`), миграции только вперёд. Правила внешнего промпта,
   расходящиеся с ними (имя ветки, обратимость миграций), действия не имеют до отдельного ответа
   заказчика (`docs/02_DEV_PROMPT.md:142`); устройство обратимости в пределах правила «только
   вперёд» описано в `docs/discovery/MIGRATION.md`, раздел 2.
6. **Раскрытие.** В хранилище переносятся только производные документы без названия, текстов,
   снимков и контрольных значений эталона. Разделы 3–4 брифа и контрольные данные промпта не
   используются; собственные контрольные значения для тестов — вопрос второго раунда (Д6,
   `docs/discovery/QUESTIONS.md`, раздел 3).

Исключение из порядка — исправление подтверждённых дефектов, не меняющее схему, денежные правила,
объём, зависимости и записанные решения (`docs/13_FULL_AUDIT.md:16-20`). Оно не требует новой
редакции `01_PROJECT.md`; очередь его исполнения — вопрос раунда 1 об очереди работ после фазы 0
(ADR-0007, ADR-0008).

## Последствия

- Объём меняется только записью в `01_PROJECT.md`; ADR без такой записи — не основание для кода.
- Каждый блок брифа стоит раунда допроса и новой редакции документа: цена — время на ответы
  заказчика, не учитываемое в `ESTIMATE.md`.
- Части брифа, которые зависят от отклонённых блоков, откладываются вместе с ними (например, работа
  бригадира в нескольких организациях зависит от ADR-0004 и ADR-0006).
- Сроки фаз брифа (бриф v2.0, §8.4) к продукту не применяются, пока заказчик не примет фазовый план.
- Оценки ADR-0002 — ADR-0008 действительны при рекомендуемых ответах; при других ответах оценка
  пересчитывается (`ESTIMATE.md`, раздел 1).

## Зависимости от решений

- Вопрос раунда 1 о том, что из брифа v2.0 допускается в публичное хранилище: место брифа и промпта.
- Вопрос раунда 1 об очереди работ после фазы 0: порядок исправления дефектов относительно ДР-11,
  ДР-12 и новых блоков.
- Вопрос 21 раунда 1 о правилах внешнего промпта, расходящихся с правилами хранилища (имя ветки,
  обратимость миграций, ввод зависимостей); до ответа действуют правила хранилища.
