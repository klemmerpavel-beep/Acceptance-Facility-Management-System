# Российское облако и отправитель писем — записка для выбора

Версия 1.0 от 07.10.2026. Назначение — дать заказчику основания для двух решений, без которых не начинается код этапа Э9: поставщик российского облака (план, пункт 6.1) и отправитель писем на домене компании (полный аудит, П-28). Третье условие — база метрик — описано в `15_BASELINE.md`.

**Как собраны данные.** Документация Yandex Cloud и VK Cloud прочитана по их открытым репозиториям документации (состояние на 06–07.10.2026). Остальное — по выдержкам поисковой выдачи с первоисточников: страницы законов и сайтов поставщиков из среды исполнителя не открывались. Такие сведения помечены «(в)». **Все цены помечены «(в)»: перед решением их сверяют в калькуляторах поставщиков.** Номера в квадратных скобках — источники в конце.

## 1. Вывод

**Рекомендация — Yandex Cloud вместе с Yandex Cloud Postbox**, с оговоркой о сверке цен. Основания:

- управляемый PostgreSQL 16 поддерживается — та же версия, что у стенда [12];
- поручение на обработку ПДн встроено в условия использования: размещая ПДн, клиент поручает обработку Яндексу — отдельного договора не нужно [13];
- меры по ПП 1119 и Приказу ФСТЭК № 21 выполнены на уровне УЗ-1, строже нужного продукту УЗ-4 [13];
- письма отправляются тем же поставщиком в том же регионе. Postbox добавляет заголовки отписки по RFC 8058 — ДР-10б требует отписку [22]. 2 000 писем в месяц бесплатно [19];
- объектное хранилище и Postbox принимают запросы с подписью одного вида (совместимой с S3 и SES v2) [16][22]. Один модуль подписи закрывает и файлы, и письма — без новой зависимости (раздел 6).

**Запасной вариант — Selectel и Unisender Go.**
- У Selectel объектное хранилище по умолчанию соответствует УЗ-1 (в) [31], поручение подписывают по обращению (в) [30], S3 — 1,25 ₽ за ГБ в месяц (в) [34].
- У Unisender Go заявлены серверы в РФ (в) [44], простой API с ключом, отписка добавляется сама (в) [45].
- Цена варианта — два договора-поручения вместо одного и два поставщика в модели угроз.

**Разделение ответственности.** Аттестат облака закрывает физический уровень, сеть и виртуализацию. За приложение, его учётные записи, модель угроз и организационные меры отвечает оператор ПДн — заказчик. Так это описывают и сами поставщики: Yandex Cloud [15], VK Cloud [23], Selectel (в) [32].

### 2.2. Технические

Требования к среде определяет устройство продукта:
- NestJS 11 на Node 22 в контейнере (`apps/api/Dockerfile`);
- PostgreSQL 16 через Prisma 6;
- файлы — снимки приёмки, чеки, сканы актов — за портом `FileStorage`. Сейчас у порта одна реализация, на диске.

Объём на первый год скромный:
- 1–2 vCPU и 2–4 ГБ памяти;
- база до 10 ГБ;
- файлы 50–100 ГБ;
- писем — от 30 до 300 в день.

## 4. Отправка писем

ДР-10б требует:
- одно письмо в день человеку, у которого в очереди есть новое или ждущее подтверждения;
- без сумм;
- с отпиской.

Это 30–300 писем в день, то есть 900–9 000 в месяц.

**SMTP почтового ящика не подходит.** Ящик рассчитан на переписку человека:
- лимит 300 писем в сутки упирается в верхнюю границу объёма;
- отписки нет;
- массовая отправка с ящика противоречит правилам поставщика (в) [48].

## 6. Что сделает исполнитель после выбора

1. **Файлы.**
   - Второй адаптер порта `FileStorage` — объектное хранилище. Вызывающий код не меняется: подключение — одна строка провайдера в `app.module.ts` (так порт и задуман).
   - Клиент S3 — новая зависимость, а новые зависимости без решения заказчика не заводятся. Вариант без зависимости — свой модуль подписи запросов, около сотни строк на `node:crypto`. Тем же модулем подписываются запросы Postbox, если выбран Yandex Cloud.
   - Выбор между зависимостью и своим модулем — за заказчиком.
2. **База.** `prisma migrate deploy` на управляемый PostgreSQL 16, перенос данных стенда не нужен — продукт заводится наполнением заказчика (план, пункт 6.3).
3. **Развёртывание.** Образ `apps/api/Dockerfile` — в контейнерный сервис облака или на сервер; секреты — переменными окружения облака, не в репозитории.
4. **Письма (ДР-10б).** Отправитель за портом по образцу `FileStorage`, адрес отправителя — на домене компании, заголовки отписки — по RFC 8058.
5. **Проверка.** `verify-api`, `verify-page` и замер `verify-baseline` — на среде облака до первых реальных данных.

## 7. Что сделать заказчику

1. Выбрать облако и почтовый сервис по разделам 3–4; сверить цены в калькуляторах.
2. Зарегистрировать организацию в облаке; выбрать регион РФ — у Timeweb Cloud явно [40], у VK Cloud — «Москва» [25].
3. Оформить поручение на обработку ПДн:
   - у Yandex Cloud оно в условиях [13];
   - у Selectel — по обращению [30];
   - у Cloud.ru — по запросу [37];
   - у VK Cloud и Timeweb Cloud — запросить явно [27].
4. Запросить у облака аттестат и перечень аттестованных услуг.
5. Подать уведомление в РКН через pd.rkn.gov.ru до начала обработки [3][11].
6. Определить уровень защищённости (ожидаемо УЗ-4) и выполнить п. 13 ПП 1119 [9]:
   - перечень лиц с доступом;
   - режим помещений;
   - учёт носителей.
7. Подтвердить домен в почтовом сервисе. В DNS — DKIM, одну запись SPF с `include` сервиса, `_dmarc` с `p=none` на первое время [21].
8. Решить вопрос зависимости для S3 и писем (раздел 6, пункт 1).
9. Подготовить порядок реагирования на утечку: уведомления за 24 и 72 часа [5][11].
