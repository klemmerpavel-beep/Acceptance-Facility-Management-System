# Приёмка — дизайн-система

Версия 1.7 от 03.09.2026 · нормативный документ для интерфейса
Основание: структурные паттерны Stworka (см. `04_REFERENCE_STWORKA.md`), собственная цветовая и типографическая основа
Изменения редакции 1.1 — в разделе 9, редакции 1.2 — в разделе 10, редакции 1.3 — в разделе 11, редакции 1.4 — в разделе 12, редакции 1.5 — в разделе 13, редакции 1.6 — в разделе 14, редакции 1.7 — в разделе 15.

Значения токенов не подбираются на ходу. Любой цвет, размер и отступ в коде берётся из переменной этого документа.

---

## 1. Принципы

1. **Деньги — первый элемент экрана.** На любом экране объекта первым, что видит руководитель, является сумма: выполнено, потрачено, остаток транша.
2. **Три касания до приёмки.** От открытия ссылки на телефоне до отметки «принято» — не более трёх касаний. Это измеряемое требование, а не пожелание.
3. **Состояние читается формой, а не только цветом.** Статус несёт пилюлю с текстом; цвет — усиление, не носитель смысла.
4. **Плотность выше воздушности.** Продукт для ежедневной работы: 132 позиции сметы должны помещаться на экране без бесконечной прокрутки.
5. **Спокойный акцент.** Один фирменный цвет, применяемый скупо. Семантические цвета состояний в акцент не входят и с ним не смешиваются.
6. **Пустое состояние — текст.** Никаких иллюстраций и маскотов: «Приёмок пока нет», «Чеки не поступали».

## 2. Цвет

Фирменный акцент — **берлинская лазурь** (глубокий стально-синий). Выбор обоснован: инженерная, чертёжная традиция; отчётливо отличается от индиго референса; не конфликтует с семантическим зелёным «принято».

### 2.1 Токены светлой темы

```css
:root{
  /* фон и поверхности */
  --bg:            #F4F6F8;   /* полотно страницы, холодный нейтрал */
  --surface:       #FFFFFF;   /* карточки, таблицы */
  --surface-2:     #EDF0F4;   /* заголовки таблиц, вторичные плашки */
  --overlay:       rgba(14,26,40,.44);

  /* текст */
  --ink:           #0E1A28;   /* основной */
  --ink-2:         #3C4C5E;   /* вторичный текст и органы управления */
  --ink-3:         #5A6979;   /* подписи и плейсхолдеры, только до 15 px */
  --ink-inv:       #FFFFFF;

  /* границы */
  --line:          #DCE2E9;
  --line-strong:   #B7C2CE;

  /* акцент */
  --accent:        #17457A;   /* берлинская лазурь */
  --accent-hover:  #10365F;
  --accent-soft:   #E4EBF4;   /* заливка выбранного, бейджи */
  --accent-ink:    #FFFFFF;   /* текст на акценте */

  /* сигнальный (внимание, срочность) */
  --signal:        #9C5E17;
  --signal-soft:   #FBEEDC;

  /* семантика состояний */
  --ok:            #2C7753;   /* принято, оплачено */
  --ok-soft:       #E1F0E8;
  --warn:          #8E670C;   /* ожидает, черновик */
  --warn-soft:     #FAF0D7;
  --danger:        #B3261E;   /* сторно, просрочено, расхождение */
  --danger-soft:   #FBE4E2;
  --neutral-soft:  #E9EDF1;   /* нейтральный статус */
}
```

Пять значений светлой темы отличаются от первой редакции: `--ink-3`, `--ok`, `--warn` и `--signal` затемнены до нормы 4,5:1 раздела 7 при сохранении тона. Обоснование и прежние значения — в разделе 9.

### 2.2 Тёмная тема

```css
@media (prefers-color-scheme: dark){
  :root:not([data-theme="light"]){
    --bg:#0D1219; --surface:#141B24; --surface-2:#1C2530;
    --ink:#E8EDF2; --ink-2:#A8B6C4; --ink-3:#7E8C9E; --ink-inv:#0D1219;
    --line:#28323E; --line-strong:#3C4854;
    --accent:#6FA3DC; --accent-hover:#8CB8E8; --accent-soft:#1B2A3C; --accent-ink:#0D1219;
    --signal:#E0A155; --signal-soft:#2E2314;
    --ok:#63B08A; --ok-soft:#172A22; --warn:#D9B24E; --warn-soft:#2B2517;
    --danger:#E0817A; --danger-soft:#2E1B19; --neutral-soft:#1E2731;
  }
}
:root[data-theme="dark"]{ /* те же значения, для явного переключателя */ }
```

Правило: **ни один цвет не определяется только внутри медиазапроса**. Базовые значения всегда в `:root`, тёмная тема их переопределяет.

Второе правило: **явно выбранная тема сообщается браузеру свойством `color-scheme`**. Токены красят только то, что нарисовано разметкой; полосы прокрутки, поля ввода и другие системные элементы браузер рисует сам по системной настройке. Без пары правил `:root[data-theme="light"]{color-scheme:light}` и `:root[data-theme="dark"]{color-scheme:dark}` выбранная светлая тема остаётся с тёмной полосой прокрутки.

Значение `--signal-soft` тёмной темы задано сплошным `#2E2314` вместо прежней полупрозрачной записи: контраст к полупрозрачной подложке не вычисляется, а значит и не проверяется.

## 3. Типографика

| Роль | Гарнитура | Обоснование |
|---|---|---|
| Интерфейс | **Golos Text** (запасные: `-apple-system, Segoe UI, Roboto, sans-serif`) | Родная кириллица, нейтральный деловой рисунок, не Inter |
| Числа, коды, таблицы | **IBM Plex Mono** (запасные: `ui-monospace, Menlo, Consolas, monospace`) | Табличные цифры, различимые ноль и буква О — критично для сумм и кодов объектов |
| Титулы и графы | **PT Sans Narrow** (запасные: `Roboto Condensed, Arial Narrow`, далее интерфейсная) | Узкий гротеск с родной кириллицей (ParaType); рисунок печатных бланков и указателей. Токен `--font-display`, применяется в `.t-h1`, `.t-h2`, `.t-cap` и подписях граф штампа — с ограничением, а не везде |

Подключение: Google Fonts, `display=swap`, обязательные запасные стеки.

### 3.1 Шкала

```
--fs-display: 32px / 1.15 / 600   — сумма на карточке объекта
--fs-h1:      24px / 1.20 / 600   — заголовок страницы
--fs-h2:      19px / 1.25 / 600   — заголовок секции
--fs-h3:      16px / 1.30 / 600   — заголовок карточки
--fs-body:    15px / 1.55 / 400   — основной текст
--fs-sm:      13px / 1.45 / 400   — вторичный, подписи полей
--fs-cap:     11px / 1.30 / 500 / letter-spacing .08em / uppercase — надзаголовки и подписи граф (--font-display)
--fs-num:     15px / 1.30 / 500 / tabular-nums — суммы в таблицах
```

Правило для сумм: `font-variant-numeric: tabular-nums`, выравнивание по правому краю, разряды неразрывным пробелом, копейки всегда две цифры — `3 758 778,00 ₽`.

## 4. Сетка, отступы, радиусы

```
--space-1: 4px   --space-2: 8px   --space-3: 12px
--space-4: 16px  --space-5: 24px  --space-6: 32px  --space-7: 48px

--radius-sm: 3px    /* пилюли, бейджи, поля ввода */
--radius-md: 4px    /* листы, кнопки */
--radius-lg: 6px    /* крупные сводные блоки; предел для всей системы */
--radius-pill: 999px

--shadow-1: 0 1px 2px rgba(14,26,40,.06);
--shadow-2: 0 4px 16px rgba(14,26,40,.10);   /* только модальные окна и меню */
```

Тени применяются скупо: листы отделяются границей `--line`, а не тенью. Углы прямые: документ не скруглён, и `--radius-lg` в 6 px — предел для всей системы. Порог удерживается проверкой страницы.

**Место под таб-панель.** Нижняя панель прибита к экрану и перекрывает конец страницы. Место под неё держит рабочее полотно: `main.container` на ширине до 767 px получает нижний отступ в высоту панели с безопасной зоной. Правило стоит на элементе, а не на классе: заголовочная обложка — тоже `.container`, и отступ ей не нужен.

**Сетка.** Десктоп: контейнер `max-width: 1440px`, поля 24 px, колонки 12. Карточка объекта: левая колонка сводки `320px`, правая рабочая — остаток. Планшет от 768 px: колонки складываются, сводка уезжает наверх. Мобильный от 360 px: одна колонка, нижняя таб-панель высотой 56 px, безопасная зона снизу учитывается.

Раскладка групп — `flex`/`grid` с `gap`. Персональные внешние отступы у элементов не используются.

## 5. Компоненты

### 5.1 Глобальная навигация

Шапка высотой 56 px, залита `--accent`. Слева логотип, по центру пилюли разделов: **Объекты · Смета · Приёмка · Расходы · Акты · График**. Активная пилюля — заливка `--surface`, текст `--accent`. Справа — пользователь и уведомления.

Мобильный: шапка сжимается до кода объекта и кнопки «назад»; внизу таб-панель из пяти пунктов с иконкой и подписью 11 px.

### 5.2 Карточка объекта — сводка

Порядок элементов сверху вниз задан жёстко:

1. **Код и адрес.** Бейдж `R-99` моноширинным на `--accent-soft`, рядом адрес `--fs-h1`.
2. **Деньги.** Три числа `--fs-display`/`--fs-h2`: `Выполнено на сумму` · `Потрачено` · **`Остаток транша`** — последнее выделено рамкой `--accent`.
3. **Статус объекта** — пилюля с текстом и кнопка смены статуса.
4. **Почтовый шлюз чеков** — карточка `--surface-2`: «Чеки отправляйте на `checks+R99@…`», код выделен бейджем, рядом кнопка «Скопировать».
5. **Срок** — карточка с числом оставшихся дней, датой дедлайна и кольцом готовности (дуга `--accent`, доля принятых позиций по сумме).
6. **Информация** — клиент, прораб, адрес, ключи, реквизиты.

### 5.3 Кольцевой индикатор готовности

Диаметр 72 px, толщина дуги 8 px, дорожка `--surface-2`, дуга `--accent`, значение в центре `--fs-h3` табличными цифрами. Считается по сумме принятых позиций к итогу сметы, не по их количеству.

### 5.4 Таблица сметы

Плотная таблица: высота строки 40 px, `--fs-sm`, суммы `--fs-num` по правому краю. Заголовок липкий, разделы — сворачиваемые группы с отступом вложенности 16 px на уровень (файл Заказчика содержит вложенность до двух уровней).

Колонки внутреннего вида: `№ · Наименование · Ед. · Кол. · Цена ед. · Ставка ЗП ед. · Сумма · ЗП · Прибыль · Принято`.
Клиентский вид: `№ · Наименование · Ед. · Кол. · Цена ед. · Сумма · Принято`.

**Внутренние колонки визуально маркируются**: фон ячеек `--surface-2` и надзаголовок группы «внутреннее» — чтобы при демонстрации экрана клиенту ошибка была заметна мгновенно. Переключатель вида — сегментированный контрол «Внутренняя / Клиентская» в шапке таблицы, состояние сохраняется на сессию.

Строка «Итого» по разделу и общий итог — закреплены снизу. При расхождении контрольной суммы итог помечается пилюлей `--danger-soft` с суммой расхождения и подсказкой.

### 5.5 Экран приёмки (мобильный, главный экран продукта)

Список позиций текущего раздела карточками. В карточке: наименование в две строки, под ним `Кол-во по смете / уже принято`, справа — крупная кнопка **«Принять»** (высота 48 px, `--accent`).

Нажатие открывает лист снизу: поле количества (по умолчанию — весь остаток), обязательное фото (камера открывается сразу), необязательный комментарий, кнопка «Подтвердить». После подтверждения — короткое подтверждающее сообщение с начисленной суммой: «Принято. Начислено 4 288 ₽ — Фархат».

Приёмка пакетная: прораб отмечает несколько позиций раздела и подтверждает их одним действием
с одной фотографией. Итого от открытия ссылки: раздел → «Принять» → «Подтвердить» = три касания
**на пакет**.

Порог относится к пакету, а не к отдельной позиции: обязательная фотофиксация требует спуска
затвора и подтверждения снимка, то есть ещё двух касаний, и при подсчёте по одной позиции
требование арифметически невыполнимо. При пакете из двенадцати позиций фактическая стоимость
отметки одной позиции падает до пяти-шести секунд, что даёт запас по метрике «не более
30 секунд на позицию».

Принятая позиция получает пилюлю `--ok-soft` «Принято» с датой и автором; действие «Сторнировать» доступно только руководителю и требует указания причины.

### 5.6 Транш

Полоса-индикатор: сумма транша, выработано, остаток. Заполнение `--accent`; при превышении 100 % — переполнение показывается `--signal`, а не ошибкой: перевыработка является нормальным событием, требующим закрытия акта.

### 5.7 Чеки и расходы

Список расходов с миниатюрой чека. Поступившие письмом попадают в статус «черновик» с пилюлей `--warn-soft` и требуют подтверждения. Письмо с неопознанным кодом объекта — в отдельной вкладке «Не распознано», не теряется.

### 5.8 График производства работ

Горизонтальная диаграмма: строка на этап (раздел сметы), полоса от даты начала до даты окончания, справа — мастер и процент готовности из приёмки. Ошибочная дата подсвечивается `--danger` с подсказкой прямо в строке.

**Масштаб.** На десктопе — шкала по дням с помесячной шапкой, подсветкой выходных и ступенчатым зумом; ширина дня задаётся токеном, зум меняет только её. На ширине до 767 px дневной сетки нет: триста дней при читаемых четырёх пикселях — это 1200 px полотна, а на телефоне у графика другой вопрос — «когда мой этап», а не «подвинуть его». Там остаётся прежняя раскладка: название, мастер, доля готовности и дорожка с полосой в процентах от срока объекта.

Прежняя формулировка «недели и месяцы, без дней» отменена редакцией 1.3: этапы двигаются и растягиваются указателем с привязкой к дню, и без дневной колонки эта привязка не выражается.

### 5.9 Прочее

- **Кнопки.** Высота 40 px (десктоп) и 48 px (мобильный). Первичная, вторичная, текстовая, опасная (`--danger`). Состояние загрузки — спиннер внутри кнопки, ширина не меняется.
- **Пилюли статусов.** Высота 24 px, `--fs-sm`, радиус `--radius-pill`, текст обязателен.
- **Поля ввода.** Высота 40 px, граница `--line`, фокус — обводка 2 px `--accent` со смещением 2 px. Денежные поля — моноширинные с маской разрядов.
- **Модальные окна.** На мобильном — лист снизу, на десктопе — центрированное окно шириной 480 px.
- **Уведомления.** Тост снизу справа (десктоп) и снизу (мобильный), 4 секунды, с действием «Отменить» там, где отмена возможна.
- **Пустые состояния.** Заголовок `--fs-h3`, пояснение `--fs-sm` цветом `--ink-3`, одно действие.
- **Скелетоны** вместо спиннеров на загрузке списков и таблиц.

### 5.10 Переключатель темы

Состояний три: **как в системе**, **светлая**, **тёмная**. Двух недостаточно: «системная» не равна «светлой», и пользователь, который тему не выбирал, обязан следовать настройке операционной системы, а выбравший — уметь вернуться к ней явно. Двухпозиционный переключатель этот возврат отнимает навсегда.

Место — шапка приложения, рядом с выходом. Управление лежит на акцентной заливке, поэтому подложка берётся из `--on-accent-fill`, а не из `--surface-2`: светлая плашка читалась бы на синей полосе как отдельная карточка.

Обозначение режима — доля закраски квадрата: половина, пусто, целиком. Рисунок остаётся в чертёжном языке набора; солнце и месяц в него не входят. Значок не единственный носитель смысла: у каждой кнопки есть скрытая подпись и `title`, состояние передаётся `aria-pressed`.

Область нажатия — 44×44 px по норме раздела 7; на ширине от 768 px сжимается до 32 px.

Выбор хранится в `localStorage` и применяется до первой отрисовки отдельным встроенным сценарием в `<head>`: разметка появляется только после загрузки модуля, и без этого выбранная светлая тема мигала бы тёмной у того, у кого тёмная выбрана в системе. Обращение к хранилищу обёрнуто в `try/catch`: в приватном режиме оно бросает исключение, а тема — удобство, из-за которого страница падать не должна.

### 5.11 Экран сводки

Первый экран отвечает на три вопроса до всякой навигации: сколько денег в портфеле, что происходит на этой неделе, где непорядок. Состав повторяет структуру референса, содержание — своё.

- **Ряд денежных карточек.** Три или четыре карточки: портфель, приёмка, расхождения смет и — только руководителю — фонд оплаты труда. Карточка несёт две величины с подписями под каждой. Число карточек в ряду определяет ширина экрана, а не медиазапрос: вёрстка не знает про роли, а отсутствующая у прораба карточка просто не приходит с сервера.
- **Недельная полоса.** Семь дней от понедельника, сегодняшний выделен акцентной подложкой. События двух видов: сроки объектов и импорты смет. Пустой день так и подписан — «событий нет»; придуманных событий в полосе нет.
- **Счётчики.** Число и подпись под ним; счётчик статуса ведёт в список объектов с уже наложенным фильтром. От метрики отличается назначением: метрика стоит в рамке внутри блока и никуда не ведёт.
- **Ближайшие сроки и лента событий.** Сроки — пять ближайших действующих объектов, просрочка красным. Лента собирается из журнала аудита и протоколов импорта: смена статуса и загрузка сметы попадают в неё сами.

Величины, которых ещё нет, показываются нулём с честной подписью, а не правдоподобным числом: «принято по актам 0,00 ₽» — это состояние продукта до этапа приёмки, а не заглушка.

### 5.12 Список объектов на телефоне

До 768 px список объектов — карточки, а не таблица. Таблица из семи колонок на ширине 360 px уводит половину сведений за край экрана: именно там, где с системой работает прораб. Набор сведений в карточке тот же, что в строке таблицы: код, статус, адрес, заказчик, прораб, срок, итог сметы. Переключение делает разметка, а не стили: держать в документе обе версии и прятать одну значило бы отдавать браузеру вдвое больше узлов.

Фильтр статусов на узком экране прокручивается вбок, а не сминается в две строки: шесть подписей со счётчиками в 360 px не помещаются.

### 5.13 Тумблер

Тумблер (`.toggle`) переключает **одно** свойство, у которого есть выключенное и включённое положение: подробный вид обмерного плана, показ внутренних полей, колонтитул в шаблоне документа. Он не заменяет сегментированный переключатель: тот выбирает один вариант из трёх и более равноправных (тема, масштаб графика, редакция замера), и подменять выбор из списка тумблером — терять варианты.

Устройство: дорожка 44×24 px, ползунок 20 px, подпись справа от дорожки. Подпись называет включаемое свойство, а не текущее положение: «Подробный», а не «Обычный / Подробный». Положение передаётся `role="switch"` и `aria-checked`; цветом дорожки — `--line-strong` в выключенном, `--accent` во включённом. На инвертированной поверхности (`.toggle--inv`) дорожка берёт `--line-inv` и `--accent-inv`: акцент светлой темы на тёмной подложке даёт контраст 2,1 и не проходит норму раздела 7.

Область нажатия — вся строка «дорожка плюс подпись», не меньше 44 px по вертикали на телефоне.

В `components.css` компонент объявляется вместе с первым потребителем — экраном замера, стадия C.1. На дизайн-канве он уже применён: артборды `Main.dc.html` и `ZamerPhone.dc.html`.

### 5.14 Список по единому образцу

Все табличные разделы — объекты, контрагенты, персонал, платежи, документы — устроены одинаково. Разное устройство списков заставляет вспоминать, где искать поиск, и прямо противоречит цели «войти в контекст за два-пять минут».

Состав панели сверху вниз: заголовок и главное действие раздела слева, число записей на странице и поиск справа; таблица; счётчик показанного справа под таблицей.

- **Сортировка — по каждой колонке.** Колонка без сортировки читается как случайное исключение. Неотсортированная колонка несёт двойную стрелку, отсортированная — одинарную; направление объявляется атрибутом `aria-sort` на ячейке заголовка, не на кнопке внутри неё.
- **Чередование строк.** Чётная строка берёт `--surface-2`. На семи колонках глаз теряет строку между кодом и итогом сметы, и чередование дешевле, чем вертикальные линии сетки.
- **Итог — в `tfoot`.** Там, где у строк есть денежная колонка, панель заканчивается итогом по показанным записям, отделённым линией `--line-strong`.
- **Строка ведёт ссылкой.** Переход по строке — `<a>` на главном поле, а не обработчик на `<tr>`: иначе список недоступен клавиатурой и не открывается в новой вкладке.
- **Сортировка и фильтрация на клиенте** — пока в разделе меньше двухсот строк. Порог назван, чтобы переход на серверную страницу был решением, а не авралом.

Число записей на странице выбирается раскрывающимся списком, а не сегментированным переключателем: значений больше трёх.

### 5.15 Экран входа

Два шага, по одному экрану на шаг: номер телефона, затем код. Блок формы шириной 420 px стоит по центру полосы, логотип — у левого верхнего края. Поясняющей прозы на экране нет: место для неё — примечание на дизайн-канве, а не первый экран, где человеку нужно ввести номер.

Номер и страна — одно поле из двух частей: список стран слева без правой границы, номер справа без левой. Номер набирается моноширинным начертанием без выравнивания вправо (`.input--tel`): правое выравнивание нужно суммам в колонке, а не вводу.

Правила номера живут в `packages/domain/src/phone.ts` одним экземпляром и применяются и на клиенте, и на сервере. Отказ называет причину: чужой код страны, городской номер, посторонние знаки, неверная длина. «Проверьте правильность данных» запрещено разделом 6.

Ответ на запрос кода одинаков для существующего и несуществующего номера. На стенде код показывается под полем с прямой подписью «Код на стенде»; в промышленной среде поле не приходит вовсе.

### 5.16 Настройки организации

Раскладка панели референса: круг логотипа 96 px слева, поля сеткой два на два справа, обязательность звёздочкой цвета `--danger`, кнопка сохранения снизу слева. Шесть вкладок: «Обзор», «Реквизиты», «Права доступа», «Уведомления», «Смета», «Интеграции».

Валюта показывается, но не правится: она одна на организацию, и суммы в разных валютах не складываются. Часовой пояс выбирается из закрытого списка: свободный ввод даёт опечатку и сдвиг всех сроков объекта.

Выпадающий список во всём продукте несёт наш шеврон, а не системную стрелку (`.selectwrap`): системная стрелка выглядит по-разному в каждой операционной системе и ломает ряд полей одинаковой высоты.

## 6. Тон интерфейсных текстов

Терминология Заказчика: **объект** (не «проект» в клиентских документах), **позиция**, **приёмка**, **акт**, **транш**, **прораб**, **мастер**, **смета**.

Кнопка называет действие, подтверждение называет результат: «Принять» → «Принято». Ошибка объясняет, что произошло и что делать: «Нельзя принять 12 м² — по смете осталось 8,4 м². Уменьшите количество или измените смету». Извинения и обтекаемые формулировки не используются.

## 7. Доступность

Контраст текста к фону не ниже 4,5:1, крупного — 3:1. Требование проверяется механически: `packages/ui/src/design-system.test.ts` считает отношение яркостей по WCAG для девятнадцати пар «текст на поверхности» в обеих темах и не пропускает недобор. Список пар ведётся руками — какой токен ляжет под какой, решает разметка, а не таблица цветов. Все интерактивные элементы достижимы с клавиатуры и имеют видимое состояние фокуса. Минимальная область нажатия на мобильном — 44×44 px. Смысл никогда не передаётся одним цветом: рядом с цветной пилюлей всегда текст. Анимации отключаются при `prefers-reduced-motion`. Все поля форм имеют программно связанные подписи.

Правило общее: крупная заливка и акцент — разные вещи; акцент остаётся на малых площадях, у выбранного пункта навигации и у ссылок. Обе пары внесены в проверку контраста.

**Ряд сводных величин (`.figrow`) вместо карточек.** Четыре величины первого экрана лежат на полотне и разделяются волосяной линией; ведущая — крупнее прочих. Четыре одинаковые рамки уравнивали величины в весе, и главную приходилось искать. Это то самое правило раздела «Поверхности по роли», которое нарушала собственная реализация.

**Полоса счётчиков (`.counterstrip`) вместо карточек-счётчиков.** Десять однозначных чисел занимали половину первого экрана. Подпись слева, число справа, строки разделены линией, строка кликабельна целиком. Компонент `.counter` удалён: у него не осталось потребителя.

**Тишина вместо повторов.** День без событий рамки не получает и подписи не несёт; пустота недели названа один раз строкой под полосой. В карточке объекта на телефоне не пишется «прораб не назначен» и «смета не загружена»: восемь таких строк подряд мешают увидеть карточки, где прораб и смета есть. Отсутствие — тоже сведение, но названное один раз.

**Лента событий ограничена и сгруппирована по дням.** Восемь последних записей, заголовок дня, время в первой колонке; остальное — в журнале объекта. Без предела лента вырастала длиннее всей страницы и состояла из почти одинаковых строк. В журнале самого объекта код объекта в каждой строке не повторяется.

**Кольцо готовности появляется с первой принятой позиции.** Круг, показывающий ноль, — рисунок пустоты; до первой приёмки плитка срока показывает срок и ничего больше.

**Поле выбора файла (`.filefield`).** Системная кнопка `input[type=file]` подписана языком браузера — «Choose File» посреди русского интерфейса — и оформлению не поддаётся. Настоящее поле скрыто, но остаётся в порядке обхода и получает видимый фокус; видимая часть — вторичная кнопка и имя выбранного файла.

**Кнопка в вертикальной группе не растягивается.** Первичное действие шириной в тысячу пикселей — мобильный приём, попавший на десктоп. Явный `.btn--block` тянуться по-прежнему может.

**Пояснения ужаты.** Подзаголовки обложек («сводка по портфелю на сегодня» под словом «Главная»), название организации рядом с лентой и трёхпредложенные пустые состояния убраны. Пустое состояние — заголовок, одно предложение, действие.

Каждое правило удерживается механически: проверка `scripts/verify-page.mjs` считает величины ряда, длину ленты и наличие группировки, число блоков с рамкой на сводке, оформленное поле файла и его достижимость с клавиатуры, отсутствие выпадающих списков с системной стрелкой.

## 14. Изменения редакции 1.6

Основание: повторное замечание заказчика о том, что продукт читается как сгенерированный. Редакция 1.5 сняла поверхностные признаки — карточную кашу, повтор фраз, системные элементы управления. Осталась причина: **у продукта не было собственного материала**. Композиция взята у конкурента, оформление собрано из умолчаний — синяя полоса, серое полотно, белые карточки со скруглением 10 px, нейтральный гротеск. Ровно этот набор воспроизводит машина, и ровно так выглядит любой B2B-дашборд, собранный за час.

Направление редакции: предметная область продукта — **рабочая документация подрядчика**. Смета есть ведомость, чертёж несёт штамп, обмер делается рулеткой, акт — бланк с графами. Оба пользователя привыкли читать документы, а не панели. Отсюда материал: интерфейс как хорошо набранный рабочий документ.

**Третья гарнитура — узкий гротеск (`--font-display: "PT Sans Narrow"`).** Кириллица родная (ParaType), рисунок близок печатным бланкам и указателям. Применяется в `.t-h1`, `.t-h2`, `.t-cap`, подписях граф штампа и заголовках колонок — с ограничением, а не везде. С Golos Text в тексте и IBM Plex Mono в числах даёт триаду «титул — текст — данные». Гарнитура подключается с `fonts.googleapis.com`: там, где сеть закрыта, работает объявленный запасной стек, и непохожесть на нём не держится.

**Углы прямые: `--radius-sm` 6 → 3 px, `--radius-md` 10 → 4 px, `--radius-lg` 14 → 6 px.** Документ не скруглён. Порог удерживается проверкой: на первом экране не должно быть блока со скруглением больше 6 px.

**Полоса шапки чернильная в обеих темах (`--band: #12202E`).** Крупная синяя плашка — приём референса и главный признак корпоративной презентации. Берлинская лазурь остаётся палитрой продукта и работает там, где несёт смысл: выбранный раздел, ссылка, шкала готовности, единственный акцентный блок экрана. Обратимость: возврат к синей полосе — правка одного токена без изменения разметки. Вторичная кнопка на полосе набирается `--band-ink` по `--on-band-track`: цветом полотна она на полосе пропадает целиком.

**`.panel` перестаёт быть коробкой.** Волосяные линии сверху и снизу, без боковых границ, без скругления, без тени. Белая заливка остаётся у `.panel--sheet` — таблиц, которым нужен лист.

**Штамп объекта (`.stamp`) вместо цветной обложки карточки.** Шесть граф — объект, адрес, стадия, срок, прораб, редакция сметы — разграфлены, подписи капсом узким гротеском, значения моноширинно. Штамп занимает место обложки и несёт те же сведения: композиция референса сохранена, материал заменён. Это единственное место, где расходуется смелость; всё остальное — тихо. Состав граф проверяется механически, пустая графа — дефект.

**Шкала готовности (`.scale`) вместо кольца (`.ring`).** Кольцевая диаграмма из одного значения — украшение; размеченная линейка с делениями на 25, 50 и 75 % читается как измерение и принадлежит миру рулетки и уровня. Правила `.ring*` удалены вместе с потребителями.

**Подпись величины называет число под собой.** Величина «Расхождения смет» показывала итог работ, а расхождение стояло второй строкой: подпись называла соседа. Исправлено на «Работы» с недосчётом импорта второй величиной; при сошедшемся пересчёте вторая величина теряет тревожный цвет и говорит, что итог сошёлся.

**Ведомость сметы закрывается своими итогами.** Три строки подвала: работы, надбавка за сопровождение, итог для заказчика; внутренние итоги — фонд оплаты труда и прибыль — стоят в своих колонках и уходят вместе с ними в клиентской проекции. Липкость объявлена на `tfoot`, а не на ячейках: три строки, закреплённые по `bottom: 0`, встали бы одна поверх другой.

**Величина, которая не может измениться, с экрана снимается.** Колонка «Принято» печатала одну и ту же пилюлю «Ожидает» во всех 132 строках; счётчики принятых позиций и актов структурно нулевые до стадии D; почтовый адрес для чеков обещал приём писем, которого на сервере нет. Всё это снято и собрано строкой в «Что дальше». Правило: место на экране занимает то, что меняется.

**Счётчик называется один раз.** Число объектов стояло в обложке раздела, в переключателе статусов, в приписке таблицы и в её подвале. Осталось два по делу: разбивка по статусам в переключателе и точный «показано с — по» в подвале. Заголовок таблицы необязателен и не ставится там, где раздел уже назван обложкой.

**Карточка объекта не повторяет штамп.** Из ведомости сведений убраны адрес, прораб и редакция сметы — они в графах штампа; строка статуса осталась только у роли, которая статус меняет.

**Бригады — ведомость, а не плитки.** У бригады два поля, и коробка вокруг двух слов добавляет к списку только рамки.

Проверка `packages/ui/src/design-system.test.ts` дополнена там, где была слепа: страницы витрины и слепка несут копию слоя стилей внутри `<style>`, и проверка мёртвых правил читала её как разметку — каждый класс «использовался» собственным же правилом. Теперь в потребители идёт только разметка, и правило без потребителя падает.

## 15. Изменения редакции 1.7

Основание: трёхконтурный аудит интерфейса от 03.09.2026 и утверждённый заказчиком реестр из 34 дефектов. Контур А — механические измерения (контраст по WCAG, зоны касания, инвентаризация ARIA, обход браузером), контур Б — правила UX-базы, контур В — разбор на шаблонность. ### 15.1 Два порога контраста вместо одного

Продукт читают на объекте при прямом солнечном свете. Норма 4,5:1 там не работает, поэтому вводится второй порог:

- **7:1** — основной текст от 15 px и **все органы управления** независимо от размера;
- **4,5:1** — подписи до 15 px и пилюли состояний, которым усиленный порог стоил бы различимости уровней.

Порог 7:1 вскрыл не отдельные пары, а целые классы: нижняя таб-панель давала 5,22, заголовки колонок реестра 5,22, фильтр статусов 6,40, вкладки 6,76. Причина одна — мелкие органы управления были набраны вторичными и подписными чернилами.

**Вторичный тон поднят до 7:1**: светлая `--ink-2` #46586B → **#3C4C5E** (лист 8,80, вторичная плашка 7,69, полотно 8,12), тёмная #A8B6C4 → **#B6C3D0** (9,66 / 7,89 / 10,47). Он же служит органам управления: `.datatable__sort`, `.segmented__option`, `.tabs__item`, `.tabbar__item`, `.stamp__crumbs`.

Отдельный токен для органов управления вводился, но оказался лишним: при пороге 7:1 он сошёлся со вторичным тоном в один цвет с разницей в три единицы яркости. Два имени для одного цвета — источник расхождения, поэтому токен снят, а роль перешла к `--ink-2`. Это правка по факту измерения, а не по замыслу: замысел был другой.

**Правило размера для `--ink-3`.** Подписные чернила применяются только до 15 px. От 15 px текст считается основным и берёт `--ink-2`.

**Правка палитры.** Светлая тема: `--danger` #B3261E → **#A5150D** (6,54 → 7,74 в обеих парах), `--ink-3` #5E6E81 → **#5A6979** (скрытый недобор 4,44 на нейтральной плашке). Тёмная тема: `--accent` #6FA3DC → **#8FBCE8** (5,51–6,56 → 7,09–8,69), `--danger` #E0817A → **#FFB4AB** (6,26 → 10,21), `--ink-3` #7E8C9E → **#8F9DAF**, `--surface-2` #1C2530 → **#212C39** — лист и вторичная плашка в тёмной теме были неразличимы.

Проверка `packages/ui/src/design-system.test.ts` ведёт 26 пар, у каждой свой порог. Прежняя редакция проверяла 21 пару одним порогом 4,5:1.

### 15.2 Зона касания

Два уровня, оба выражены токенами и переключаются медиазапросом, а не выбором класса при разметке:

- **до 1023 px включительно** — `--control-h`, `--row-h` и `--tap-min` равны **48 px**: продукт держат в руках;
- **от 1024 px** — **44 px**: цель берут курсором.

Токен `--control-h-touch` объявлялся, но применялся ровно в одном месте продукта, поэтому размер задаётся не им.

Отдельное правило: **цель нажатия не равна высоте текста**. Заголовок колонки реестра давал 45×16 при семи целях в шапке, пункт навигации 88×32, переключатель темы 32×32, ссылка адреса в узкой раскладке 294×21. Все интерактивные элементы берут `min-block-size` и, где подпись короткая, `min-inline-size` из `--tap-min`; у заголовка колонки рост компенсируется отрицательными отступами, чтобы шапка таблицы не выросла.

Два исключения признаются и не считаются дефектом: ссылка внутри строки текста (её размер задаёт кегль абзаца — исключение «inline» критерия 2.5.8) и поле внутри подписи-обёртки, когда цель нажатия — обёртка.

### 15.3 Обложка раздела уходит с чернильной полосы

Шапка и обложка были одного цвета `--band` и сливались в блок 140 px на десктопе и 90 px на телефоне; в тёмной теме граница с полотном исчезала. Обложка переносится на полотно и отделяется волосяной линией. Чернильной остаётся только шапка.

### 15.4 Пилюля состояния — прямоугольник

`--radius-pill` у `.pill` заменён на `--radius-sm`. В системе с предельным радиусом 6 px капсула была единственной круглой формой и читалась как заимствование из чужой панели. Текст в пилюле сохраняется: статус не передаётся одним цветом.

### 15.5 Граница представления списка

Список объектов показывается ведомостью до **1023 px**, а не до 767. На планшете таблица из семи колонок не складывалась, а сжималась: адрес рвался на три строки, срок на четыре, высота строки росла с 49 до 90 px. Планшет — рабочее устройство прораба, и на нём раскладка была худшей из трёх. Граница навигации не меняется: разделы уходят в нижнюю таб-панель по-прежнему на 767 px. Это две разные границы, и их совпадение было случайным.

Объект в узкой раскладке — строка ведомости `.objectrow`, а не карточка: восемь белых коробок с рамкой на сером полотне повторяли приём, от которого продукт отказался на десктопе. Ссылкой служит вся строка (цель была 294×21).

### 15.6 Необратимое действие называет последствия

Запись сметы проходит через подтверждение, которое перечисляет: сколько позиций будет записано, каков недосчёт итога по файлу, сколько решений по единицам применится, и что прежняя редакция остаётся в протоколе. Кнопка называет действие — «Записать смету», а не «Импортировать».

Правило общее: действие, меняющее основание расчётов, показывает состав изменения до того, как оно произойдёт.

### 15.7 Состояния объявляются, а не только рисуются

`aria-live` и `role="status"` не встречались в продукте ни разу, `aria-describedby` и `aria-invalid` — тоже. С этой редакции: ошибка поля связана с полем через `aria-describedby` и помечает его `aria-invalid`; подтверждение действия несёт `role="status"`; полоса загрузки несёт `aria-busy` и доступное имя.

Отказ сети и неожиданный ответ сервера — разные события и разные тексты. Строка браузера «Failed to fetch» пользователю не показывается.

### 15.8 Шаблон вкладок целиком

`role="tab"` без `aria-controls`, `role="tabpanel"` и управления стрелками — не шаблон вкладок, а его половина. С этой редакции вкладка связана с панелью, панель названа вкладкой, выбор переводится стрелками, а Tab уводит из полосы вкладок в её содержимое.

Модальный диалог удерживает фокус и возвращает его открывшей кнопке.

### 15.9 Проверка при последующих правках

Механические правила держатся тестом, но тест надо не забыть запустить. Хук `.githooks/pre-commit` запускает проверку дизайн-системы сам и только тогда, когда в фиксацию попал слой представления — `packages/ui/`, `apps/web/src/` или `design/`. Если стенд поднят, следом идёт проверка страницы; если нет — хук называет пропущенную проверку, но фиксацию не блокирует.

Включается на машине разработчика один раз: `git config core.hooksPath .githooks`. Обход в исключительном случае — `git commit --no-verify`.

### 15.10 Что не менялось и почему

Три пункта реестра выходят за слой представления и остались нетронутыми: обнаружение конфликта версий записи (требует контракта API), адресация состояния экрана (меняет навигационный контракт), массовое редактирование реестра (требует обработчиков на сервере). Виртуализация таблицы сметы отложена: при 176 строках выигрыш не оправдывает риска сломать липкую шапку, сворачиваемые разделы и подытоги; порог в 400 строк назван на экране.
